qudi# 子任务 10：交互优化与性能收尾

## 执行目标
实现以下增强功能：历史记录存储、首页交互、诊断可追溯点击、年龄联动刷新、融像范围格式提示、报告打印优化、全局样式打磨与性能优化。

## 依赖
- 子任务 01-09 全部完成

## 详细 Prompt

### 1. 历史记录存储（localStorage）
- 每次完成诊断后，自动保存 `gExamData` 到 `localStorage`，key 为 `oculus_exam_{timestamp}`
- 保存内容：`{ timestamp, basic, accommodation, convergence, binocular, diagnosis }`
- 首页"历史记录"入口：从 localStorage 读取所有记录，按时间倒序显示列表
  - 每条记录显示：检查日期 + 年龄 + 诊断摘要（如"调节不足 + 集合不足"）
  - 点击可加载该记录并跳转到 report 页
  - 支持删除单条记录（滑动删除或长按删除）
- 最多保留 50 条记录

### 2. 首页交互完善（page-home）
- "新建检查"按钮：清空 `gExamData`，跳转到 `page-input`
- "历史记录"列表：如上
- 如果有历史记录，显示最近一次检查的简要摘要卡片

### 3. 诊断可追溯
- 在 `page-diagnosis` 中，每个诊断结论（如"调节不足"）可点击
- 点击后展开/滚动到该类型的必要条件/充分不必要条件详细判定区域
- 使用 smooth scroll + 高亮闪烁效果

### 4. 年龄联动刷新
- 在 `page-input` 中修改年龄时：
  1. 重新计算 AMP 期望值并更新显示
  2. 重新调用 `analyzeAbnormalities` 刷新所有异常标注
  3. 所有依赖年龄的正常值范围（如 AMP）同步更新提示文本

### 5. AC/A 方法切换联动
- 切换计算法/梯度法时：
  1. 正常值范围文本更新（计算法 5~7 / 梯度法 3~5）
  2. 辅助计算公式区域切换
  3. 已输入的 AC/A 值保留但重新判定异常

### 6. 融像范围输入提示
- BI/BO 输入框的 placeholder 提示格式："模糊/破裂/恢复"
- 输入验证：3 个值必须为数字且 模糊 ≤ 破裂，不满足时 Toast 提示

### 7. 报告打印/导出优化
- `@media print` CSS：
  - 隐藏 header、footer、bottom-bar、所有按钮
  - 报告卡片全宽、无阴影、有边框
  - 强制白底黑字
  - 页面断点控制（`break-inside: avoid`）
- 导出按钮文字改为"打印/导出报告"

### 8. 专业术语内联解释
- 对关键术语添加 `.term-tip` 类，点击后弹出简短解释 Tooltip
- 需要解释的术语及内容：
  - NRA："负相对调节，双眼同时放松调节的能力，正常值 +2.00~+2.50D"
  - PRA："正相对调节，双眼同时刺激调节的能力，正常值 ≥2.50D"
  - BCC："调节反应（MEM动态检影），衡量调节滞后/超前，正常值 +0.25~+0.75D"
  - AMP："调节幅度，眼睛最大调节能力，期望值 = 15 - 0.25×年龄"
  - AC/A："调节性集合与调节的比值，计算法正常5~7△/D，梯度法正常3~5△/D"
  - NPC："集合近点，双眼最大集合能力的近点距离，正常5~7cm"
  - Sheard准则："融像储备应≥2倍隐斜量，适用于外隐斜"
  - 1:1准则："BI恢复值应≥内隐斜量，适用于内隐斜"
- Tooltip 样式：黑色半透明背景 + 白色文字 + 箭头指向术语，点击空白关闭

### 9. 全局样式打磨
- 页面切换动画优化：添加 slide 左右滑动效果（前进向左滑出/后退向右滑出）
- 滚动优化：所有可滚动区域使用 `-webkit-overflow-scrolling: touch`
- 长列表性能：历史记录列表超过 20 条时虚拟滚动（简单实现：只渲染可视区域 ±5 条）
- 输入防抖：异常标注计算使用 300ms debounce，避免频繁触发
- 首次加载：显示简短 splash（Oculus 图标 + "视功能分析工具"），0.5s 后消失
